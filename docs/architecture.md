# 애플리케이션 구조와 한계

2025년 졸업 프로젝트의 Flask·Streamlit 구조를 유지하면서 백엔드와 화면의 데이터 경계를 정리했습니다.

## 연결

Streamlit은 Requests 클라이언트로 API를 호출합니다. 상품 목록·상세·카테고리·추천·리뷰 분석·가져오기의 데이터 기준은 백엔드입니다. 기존 UI가 로컬 TSV와 독립 index만 읽던 흐름과 달리 같은 SQLite 상태를 공유합니다.

Flask 앱은 팩토리 형태로 설정과 서비스를 조립합니다. 저장소는 상품, 리뷰, 추출 결과를 나누며 parameterized SQL과 transaction으로 처리합니다. 중복 가져오기는 같은 리뷰를 다시 늘리지 않도록 관리합니다. 초기 데모는 빈 DB에만 추가하며 사용자 DB를 지우지 않습니다.

기존 TSV 유틸은 호환 도구로 남아 있습니다. ACOS span은 끝 인덱스를 포함하지 않는 [start,end)이며, (-1,-1)은 암시적 span입니다. 문장을 상품 식별자로 대신 쓰는 경우에는 전체 텍스트의 안정된 digest를 사용하지만 실제 상품 ID와 동등한 것은 아닙니다.

## 분석과 추천

규칙 분석은 입력의 속성·의견 표현을 연결하는 baseline입니다. 고정된 배터리/화면 예시를 모든 입력에 반환하지 않습니다. 아무 표현도 찾지 못하면 빈 결과를 반환합니다.

실제 predictor는 별도 경계에 연결합니다. 가중치와 환경이 없으면 실제 모델을 제공하는 것처럼 보이지 않게 연결 상태·실패를 표시합니다. upstream 모델의 benchmark는 이 앱의 평가 결과로 사용하지 않습니다.

추천은 선택 특성에 맞는 저장 리뷰와 감정 집계에 근거합니다. AND는 선택 카테고리 전체, OR은 일부 조건 일치를 뜻합니다. 결과 카드의 점수와 근거는 규칙 집계이며 구매 확률·사용자 만족도 예측이 아닙니다.

## 남은 한계

- pretrained ACOS 모델 가중치와 재현 환경은 포함하지 않습니다.
- 단순 표현 규칙은 문맥·부정·암시적 속성·복합 감정을 놓칠 수 있습니다.
- 데모 리뷰는 합성이며 실제 판매 상품·평점·구매 성과가 아닙니다.
- 로컬 SQLite와 단일 서버 구성입니다. 사용자 인증·권한·공유 데이터의 감사 정책은 운영 확장 과제입니다.
- 추출 정확도·추천 품질·사용자 실험·고부하 성능을 검증한 버전은 아닙니다.
- 실제 데이터의 이용 권한과 개인 정보 처리·백업은 사용 전에 별도로 확인해야 합니다.
