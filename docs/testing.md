# 테스트와 실행 범위

저장소 루트에서 개발 의존성을 설치한 뒤 실행합니다.

~~~powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
~~~

## 자동 검사

2026-10-13 로컬 실행에서 127개 테스트가 통과했습니다.

- Flask API의 정상 응답, 입력 검증, CORS, 오류 형식, 요청 크기 제한
- SQLite 저장·집계·추천 근거, 중복 가져오기, 충돌 시 전체 롤백, 기존 DB 보호
- 규칙 분석의 입력별 결과와 모델 adapter의 로드·실패 경계
- API 클라이언트의 연결 오류·시간 초과·일반 텍스트 413 처리
- JSON/TSV 가져오기, ACOS의 end-exclusive span, implicit aspect, 안정적인 상품 ID
- Streamlit AppTest의 분석·추천·상세·가져오기 및 화면·도메인 상태 초기화
- 통합 실행기의 환경변수 우선순위, 포트 검사, 서비스 준비 대기와 자식 프로세스 정리

GitHub Actions는 Python 3.11에서 Windows와 Linux 테스트를 실행합니다. 테스트용 임시 DB와 합성 데이터를 사용하며 모델 다운로드나 GPU 학습은 수행하지 않습니다.

## 실제 브라우저 확인

2026-10-13 Windows에서 Waitress와 Streamlit을 띄워 Chromium 기반 브라우저로 다음 흐름을 확인했습니다.

1. 서비스 상태 확인과 실제 API의 분석·추천 응답
2. 상품 탐색에서 상세 리뷰 열기
3. 문장 입력 후 API 결과 두 개 표시
4. 특성 선택 후 추천 카드와 근거 표시
5. 업로드 미리보기만으로 DB가 바뀌지 않는지 확인
6. 명시적인 가져오기 후 상품 저장·목록 갱신
7. 도메인 변경 시 이전 상품·상세 상태가 남지 않는지 확인

브라우저 JavaScript 오류는 없었습니다. [탐색 화면](images/overview.png)과 [분석 화면](images/analysis.png)은 이 확인 과정에서 캡처했습니다. 이 브라우저 검사는 별도 로컬 점검이며 CI에 브라우저 의존성을 추가하지 않았습니다.

## 검증하지 않은 범위

별도로 `run.py`가 실제 두 서버를 시작하는지, Ctrl+C 처리 후 두 서버가 종료되는지도 확인했습니다. 실제 HTTP에서 1,999,999와 2,000,000 bytes 요청은 200, 2,000,001 bytes 요청은 413으로 거절됐습니다.

학습 모델 가중치가 없어 모델 정확도·추론 속도·논문 benchmark 재현은 검증하지 않았습니다. 규칙 baseline의 동작 검사는 모델 성능 평가가 아닙니다. 외부 공개 서비스 운영, 사용자 인증, 실제 대용량 리뷰 부하·동시 쓰기 성능도 별도 검증이 필요합니다.
